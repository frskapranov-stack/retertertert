# Починить домашний Keenetic

Облачный агент **не видит** `192.168.3.1` — это адрес вашей домашней сети. Скрипт нужно запустить с Mac или ПК, который сидит в этом Wi‑Fi.

Он:

1. Поднимает VPN, если туннель лежит (из‑за этого «опять ничего не работает»).
2. Возвращает обычный интернет через провайдера, если политика хотспота уехала в VPN.
3. Добавляет **Instagram** и **Cursor** в маршруты DNS уже существующего VPN.
4. Сохраняет конфиг и **перезагружает** роутер. Без reboot Keenetic часто не применяет `dns-proxy route`.

Пароль роутера в git не пишется.

## Mac

1. Скачайте из этой ветки `vpn_fix.py`, `fix-router.command` и папку `vpn/`.
2. Рядом должны лежать все три.
3. Двойной щелчок по `fix-router.command` (или в Терминале: `chmod +x fix-router.command && ./fix-router.command`).
4. Введите пароль `admin` на `192.168.3.1`.
5. Подождите 1–2 минуты, пока роутер перезагрузится.

Только диагностика, без изменений:

```bash
python3 vpn_fix.py --diagnose
```

Без перезагрузки (маршруты DNS могут не подхватиться):

```bash
python3 vpn_fix.py --no-reboot
```

## Windows

Двойной щелчок по `vpn-routes.vbs` (нужен Python 3). Либо:

```bat
py -3 vpn_fix.py
```

## Если удобнее руками (KeeneticOS 5)

Веб-интерфейс → **Сетевые правила → Маршрутизация → Маршруты DNS**.

Вставьте домены из `vpn/instagram-domains.txt` и `vpn/cursor-domains.txt` в списки, правило на VPN, включите «Добавлять автоматически», затем перезагрузите роутер.

На телефонах и ПК DNS должен быть **роутер**, не Private DNS / DoH в браузере. На iPhone: Настройки → Сотовая / Wi‑Fi → DNS → автоматический. На Android: Private DNS → выкл.

## Почему прошлый скрипт не сработал

`vpn-routes.vbs` из PR #3 — это Windows Script Host. На Mac он не запускается. Плюс маршруты DNS на Keenetic часто оживают только после reboot, а мёртвый WireGuard превращает Instagram/Cursor в «ничего не открывается».
